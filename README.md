# IC-FLD Thesis Workspace

This repo contains every component I use to study **Inter-Channel Functional Latent Dynamics (IC-FLD)**, compare it against the original **FLD** baseline, and benchmark against reference models such as GraFITi and tPatchGNN. All models share the same preprocessing (`lib/parse_datasets.py`) and the same evaluation helpers (`lib/evaluation.py`), so metrics are directly comparable across trainers.

---

## Quick Start

1. **Clone & install**
   ```bash
   git clone <repo-url> && cd MasterThesis-1
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. **Prepare data**  
   Unzip `data.zip` (or copy your processed `data/` folder) into the repo root. Verify paths with:
   ```bash
   python scripts/check_data_paths.py
   ```
3. **Verify GPU/conda setup (optional)**  
   `python -c "import torch; print(torch.cuda.is_available())"`

## Training the main models

All trainers now expose `--patience` (patience for early stopping) and log `loss/mse/rmse/mae/mape` via `lib/evaluation`. Outputs land in `FLD*/saved_models/` plus `runs/` if TensorBoard is enabled, and a metrics row is appended through `write_result.py`.

### IC-FLD
```bash
python FLD_ICC/train_FLD_ICC.py \
  -d physionet -ot 24 -bs 32 --epochs 1000 --patience 15 \
  -fn L -ed 64 -ld 128 -nh 4 --depth 2 \
  --lr 1e-4 --wd 1e-3 --gpu 0 \
  --tbon --logdir runs/icfld_physionet_L
```
Key flags:
- `-fn {C,L,Q,S}` selects the basis.
- `--use-patchify/--num-patches` toggles patch memory.
- `--patience` controls early stopping (defaults to `--early-stop` value if not provided).

### FLD baseline
```bash
python FLD/train_FLD.py \
  -d physionet -ot 24 -bs 32 -fn L \
  -e 1000 --patience 10 --learn-rate 1e-4 --weight-decay 1e-3 \
  --gpu 0 --tbon --logdir runs/fld_physionet_L
```
The FLD model now calls the same `lib.evaluation` utilities, so its metrics match IC-FLD and the baselines.

### Other baselines
- `grafiti/train.py`, `mtan/`, and `tPatchGNN/run_models.py` already consume the shared dataloaders. See each folder’s README or script header for CLI options.
- `scripts/run_best_hparams.sh` / `.ps1` replay the best hyper-parameters captured in the JSON bundles under `best_hparams_*.json`.

## Metrics, checkpoints, and logs

- **Checkpoints** – saved per run inside `FLD_ICC/saved_models/` or `FLD/saved_models/` (`*.best.pt` and `*.latest.pt`).
- **Metrics** – every trainer records `loss/mse/rmse/mae/mape` for train/val/test using `lib/evaluation`. These scalars are min–max normalized (same as the inputs) and averaged per-channel before averaging across channels.
- **Result CSV/JSON** – `write_result.py` appends aggregated metrics + CLI params to a central log (see `write_result.py` for storage location) and prints a JSON summary for scripting.
- **TensorBoard** – enable with `--tbon --logdir runs/<name>`; standard tags (`train/*`, `val/*`, `test/*`, diagnostics for IC-FLD memory/attention) are emitted every epoch.

## Hyper-parameter sweeps & scripts

- `scripts/optuna_icfld.py` – grid-search driver across all datasets/functions for IC-FLD (and optionally FLD).  
  Example: `python scripts/optuna_icfld.py --trials 10 --trainer icfld`.
- `scripts/optuna_ushcn.py` – simplified sweep dedicated to USHCN (supports both trainers).  
  Example: `python scripts/optuna_ushcn.py --trainer fld --trials 20`.
- `scripts/run_best_hparams.sh` / `.ps1` – replay the JSON lists generated by the sweeps or your own config files.
- `scripts/benchmark_fld_vs_icfld_physionet.sh` / `.ps1` – convenience wrappers to train both models on PhysioNet for every basis function.

All sweep scripts write checkpoints in the usual `saved_models/` directories and rely on the default logging pipeline described above.

## Cluster / batch usage (optional)

The `cluster/` folder contains pre-made SLURM scripts. The workflow is:

1. **Sync code & data**
   ```bash
   rsync -avz --exclude='.git/' --exclude='runs/' ./ <user>@cluster:~/MasterThesis-1/
   rsync -avz data/ <user>@cluster:~/MasterThesis-1/data/
   ```
2. **Create env on the cluster**
   ```bash
   conda create -n thesis python=3.10
   conda activate thesis
   pip install -r requirements.txt
   ```
3. **Submit jobs**
   ```bash
   sbatch cluster/submit_icfld_array.sh    # 16 dataset/function combos
   sbatch cluster/submit_fld_array.sh
   # or single jobs:
   sbatch cluster/submit_icfld_single.sh physionet L
   ```
4. **Monitor / fetch logs**
   ```bash
   squeue -u $USER
   tail -f cluster/logs/icfld_array_<job>_<task>.log
   rsync -avz <user>@cluster:~/MasterThesis-1/FLD_ICC/saved_models ./results/icfld/
   ```

Each SLURM script sets up logging under `cluster/logs/` and respects the same CLI flags shown above, so the behavior is identical to local runs.
